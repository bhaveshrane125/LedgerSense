# LedgerSense PO and GRN PDF Rendering Plan

## 1. Objective

Extend the synthetic data generator so it can optionally render matching purchase order PDFs and goods receipt note PDFs alongside invoice PDFs.

The new PDF outputs must use the same synthetic master data, PO records, GRN records, manifest, and dataset summary generated by the current pipeline.

This feature must remain optional:

```bash
python3 synthetic_data.py --pdf-count 40 --output data/output/demo --render-po-pdfs --render-grn-pdfs
```

Default behavior should stay unchanged: invoice PDFs only.

---

## 2. Scope

### Included

- PO PDF rendering
- GRN PDF rendering
- CLI flags for enabling each document type
- Output directories for PO and GRN PDFs
- Manifest fields for related PO/GRN PDF paths and SHA-256 hashes
- Dataset summary counts for rendered PO and GRN PDFs
- Validation that enabled PDF counts match generated records
- Clear handling of `MISSING_GRN` scenarios

### Not Included

- Real ERP integration
- OCR or extraction
- Real supplier/customer data
- Human approval workflow
- Matching or exception decisioning

---

## 3. Output Structure

Use the existing planned folders:

```text
data/output/demo/
├── pdfs/
│   ├── invoices/
│   ├── purchase_orders/
│   │   ├── PO-000001.pdf
│   │   ├── PO-000002.pdf
│   │   └── ...
│   └── goods_receipts/
│       ├── GRN-000001.pdf
│       ├── GRN-000002.pdf
│       └── ...
├── ground_truth/
│   ├── invoices/
│   ├── purchase_orders/
│   └── goods_receipts/
└── mock_erp/
```

For duplicate invoices, do not create duplicate PO/GRN PDFs unless the implementation intentionally creates duplicate PO/GRN records. Reuse the related PO/GRN references.

For `MISSING_GRN`, no GRN PDF should be created.

---

## 4. CLI Changes

Add flags:

```bash
--render-po-pdfs
--render-grn-pdfs
```

Examples:

```bash
python3 synthetic_data.py --pdf-count 40 --output data/output/demo --render-po-pdfs
python3 synthetic_data.py --pdf-count 40 --output data/output/demo --render-grn-pdfs
python3 synthetic_data.py --pdf-count 40 --output data/output/demo --render-po-pdfs --render-grn-pdfs
```

YAML config already includes:

```yaml
rendering:
  render_po_pdfs: false
  render_grn_pdfs: false
```

CLI flags should override YAML values to `true`.

---

## 5. PO PDF Requirements

Each purchase order PDF must visibly contain:

```text
SYNTHETIC TEST DOCUMENT - NOT FOR PAYMENT
```

Required visible fields:

- PO number
- PO date
- Vendor ID and vendor name
- Vendor tax ID
- Currency
- Payment terms
- Line number
- SKU
- Item description
- Ordered quantity
- UOM
- Unit price
- Tax rate
- Line total
- PO total amount

Suggested filename:

```text
PO-000001.pdf
```

Ground-truth JSON filename:

```text
PO-000001.json
```

---

## 6. GRN PDF Requirements

Each GRN PDF must visibly contain:

```text
SYNTHETIC TEST DOCUMENT - NOT FOR PAYMENT
```

Required visible fields:

- GRN number
- Linked PO number
- Receipt date
- Vendor ID and vendor name if available through the linked PO
- Line number
- Item ID or SKU
- Quantity received
- Quantity rejected
- UOM
- Condition note

Suggested filename:

```text
GRN-000001.pdf
```

Ground-truth JSON filename:

```text
GRN-000001.json
```

---

## 7. Renderer Design

Reuse the current simple PDF writer in `generator/pdf_renderer.py`.

Add two new public functions:

```python
render_purchase_order_pdf(
    purchase_order: PurchaseOrder,
    vendor: Vendor,
    output_directory: Path,
) -> Path

render_goods_receipt_pdf(
    goods_receipt: GoodsReceipt,
    purchase_order: PurchaseOrder,
    vendor: Vendor,
    output_directory: Path,
) -> Path
```

Keep the low-level `_write_simple_pdf()` function shared across invoice, PO, and GRN rendering.

---

## 8. Ground Truth Changes

Add:

```python
save_purchase_order_ground_truth(...)
save_goods_receipt_ground_truth(...)
```

PO ground truth should include:

- PO object
- Vendor object
- Related invoice document IDs if useful

GRN ground truth should include:

- GRN object
- Linked PO number
- Vendor context
- Scenario context when missing or mismatched documents are being tested

Do not write GRN ground truth for `MISSING_GRN` because no GRN exists.

---

## 9. Manifest Changes

Extend each invoice manifest row with optional fields:

```json
{
  "po_pdf_path": "pdfs/purchase_orders/PO-000001.pdf",
  "po_pdf_sha256": "abc...",
  "grn_pdf_path": "pdfs/goods_receipts/GRN-000001.pdf",
  "grn_pdf_sha256": "def..."
}
```

When PO or GRN rendering is disabled, use `null`.

When scenario is `MISSING_GRN`, use `null` for GRN PDF fields.

---

## 10. Dataset Summary Changes

Add counts:

```json
{
  "requested_pdf_count": 40,
  "generated_pdf_count": 40,
  "generated_po_pdf_count": 40,
  "generated_grn_pdf_count": 36,
  "missing_grn_count": 4
}
```

Validation rules:

- If `render_po_pdfs` is true, PO PDF count must equal the number of unique generated PO records.
- If `render_grn_pdfs` is true, GRN PDF count must equal the number of generated GRN records.
- Invoice PDF count must still equal `pdf_count`.

---

## 11. Implementation Steps

1. Add CLI flags in `generator/main.py`.
2. Update `apply_overrides()` to accept PO/GRN rendering booleans.
3. Add PO and GRN PDF render functions in `generator/pdf_renderer.py`.
4. Add PO and GRN ground-truth save functions in `generator/ground_truth.py`.
5. Track unique PO and GRN records during dataset generation.
6. Render each unique PO only once when `render_po_pdfs` is enabled.
7. Render each GRN only once when `render_grn_pdfs` is enabled.
8. Attach PO/GRN PDF paths and hashes to invoice manifest rows.
9. Add summary counts.
10. Add validation checks for enabled output counts.
11. Add tests for invoice-only default behavior.
12. Add tests for PO-only, GRN-only, and PO+GRN rendering.
13. Add tests that `MISSING_GRN` creates no GRN PDF.

---

## 12. Acceptance Criteria

The feature is complete when:

1. Existing invoice-only generation still works without new flags.
2. `--render-po-pdfs` creates one PDF per unique PO.
3. `--render-grn-pdfs` creates one PDF per generated GRN.
4. `MISSING_GRN` scenarios do not create GRN PDFs.
5. PO and GRN PDFs contain the synthetic-document marking.
6. PO and GRN PDFs are non-empty valid PDF files.
7. Ground-truth JSON exists for rendered PO and GRN documents.
8. Manifest records include PO/GRN PDF paths and hashes where applicable.
9. Dataset summary reports PO/GRN counts.
10. Tests pass for all combinations of rendering flags.

---

Implement the minimum useful version first:

```bash
python3 synthetic_data.py \
  --pdf-count 40 \
  --seed 42 \
  --output data/output/demo_with_po_grn \
  --render-po-pdfs \
  --render-grn-pdfs
```

Expected result:

```text
40 invoice PDFs
40 invoice ground-truth JSON files
40 PO PDFs, except duplicate-reuse rules may reduce unique PO PDFs
GRN PDFs for all non-MISSING_GRN records
PO and GRN ground-truth JSON files
1 manifest.jsonl with invoice, PO, and GRN paths
1 dataset_summary.json with invoice, PO, and GRN counts
```
